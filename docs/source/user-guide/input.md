# Input Files

Input files for Kingfisher are constructed using `yaml`.
Individual characteristics of the simulation are addressed in "blocks" within the input file.
Blocks, including descriptions and requirements, are discussed in detail below.

(input-version)=
## Version
The `version` block sets the schema version to check the input file against.
For now, only version 0 is available.

```{schema-block} version
```

(input-problem)=
## Problem
The `problem` block holds simulation-wide settings.
It includes:
1. `name` - The user-set name of the simulation.
2. `mode` - The type of simulation that can be run. 

```{schema-block} problem
```

(input-mesh)=
## Mesh
The `mesh` block holds any information related to the mesh.
It includes only one entry (for now):
1. `filename` - The mesh file name, including its relative path.

For now, the only type of mesh supported is a `.msh` file generated by `gmsh`.
See {doc}`meshes` for more information on how Kingfisher expects meshes to be formatted.

```{schema-block} mesh
```

(input-boundary-conditions)=
## Boundary Conditions
The `boundary_condition` block contains the list of all boundaries in the simulation.
As discussed in {ref}`user-guide/meshes:Boundary Conditions and Regions`, the mesh on which the simulation is run must contain information about where boundary conditions are.
The `name` field in the boundary condition **must** match the prefix-free name in the mesh.
For example, if the mesh contains a group named `boundary_condition:reflector`, the name in the block must be `reflector`.

```{schema-block} boundary_conditions
```

(input-materials)=
## Materials

The `materials` block contains the list of all available materials in the simulation.
In addition to a unique name, each material item must hold information about its cross sections.
Total cross section values, $\Sigma_t$, must be listed in *ascending* energy group order (that is, the cross section corresponding to the lowest-energy group should be listed first).

The scattering cross sections are more complicated because values must be given as Legendre moments.
Three nested arrays must be given and are indexed as `[Legendre moment number][from energy group][to energy group]`.

Note that all cross section values must be give in 1/cm!

(input-sources)=
## Sources
The `sources` block is *optional* and contains information about any independent sources in the simulation.
Note that any impinging sources, such as a beamline on a surface, must be handled by the `boundary_conditions` block.
The `sources` block is reserved for within-volume sources, such as volumetric and point sources.

```{schema-block} sources
```

(input-regions)=
## Regions

A "region" in Kingfisher is physical grouping of a material and (optionally) a source(s).
Like boundary conditions, a region for an element is specified in the mesh itself using the `regions:` prefix (see {ref}`user-guide/meshes:Boundary Conditions and Regions`).
The `name` of a region must match the prefix-free name in the mesh to be valid.
For example, `region:MOX fuel` must be named `MOX fuel`.


```{schema-block} regions
```

(input-angular)=
## Angular

The `angular` block holds information needed for the angular treatment of the transport equation.
For now, Kingfisher is limited to a discrete ordinates ($S_N$) formulation. 
Two types of angular quadrature sets can be defined, one which defines a set over the *entire* unit sphere, and the other which defines uniques sets over the polar and azimuthal angles, then creates the total quadrature set using a tensor product.
The former is built with a Lebedev quadrature set (not yet supported), while the latter can be any combination of quadrature sets in 1D.
For example, a common choice is to pick a Gauss-Legendre set for the polar direction, and a trapezoid rule for the azimuthal direction.


(input-spatial)=
## Spatial

The `spatial` block holds the settings for the spectral elements in space.
For now, only the Gauss-Lobatto-Legendre set is available, but users can set the polynomial order for the individual elements.

```{schema-block} spatial
```

(input-solver)=
## Solver

The `solver` block holds settings specifically for the numerical solver, notably for source iterations in both k-eigenvalue and fixed-source run modes.


```{schema-block} solver
```

(input-output)=
## Output

The `output` block has users specify the output file format, along with the information desired.
All values expected in the output must be included in the `export_values` array item in the block.

```{schema-block} output
```
